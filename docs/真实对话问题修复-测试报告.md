# 句子秒聘·真实对话问题修复与测试报告

> 2026-07-28｜执行：Codex｜状态：本地实现与隔离环境测试通过，未提 PR、未部署｜代码提交：`153863e`

## 一、结论

本轮针对真实候选人对话暴露的问题做了代码修复：

1. 好友通过后不再拿 `externalUserId` 错调只认 `chatId` 的接口，改用秒回现行 `/message/sendByWecom`，按「托管员工 userId + externalUserId」主动发送。
2. 主动邀约失败后保留 `CONFIRMED` 状态，每 10 秒补偿重试，最多 4 次；服务重启后仍能从 Mongo 恢复，连续失败只通知 HR 一次。
3. 已约成、等待改期拍板或已拒绝结束后，候选人只回“好 / 嗯嗯 / 谢谢”等礼貌确认时静默，不再反复客套。
4. 只接收秒回文本类型 `7`（兼容旧类型 `0`）的 `payload.text/pureText`；图片类型 `11` 的哈希 `payload.content` 不再进入模型。
5. 时间解析新增 `这周四15.30`、中文句号分隔等格式，候选人原话完整保留；确定性意图不再把“好的，那薪资多少”按前缀误判为确认。
6. HR 在秒回工作台主动发起或回复会话时，立即把该候选人切为转人工，之后 AI 停止接待。AI 回声按候选人的 `chatId/externalUserId` 隔离，避免甲乙收到相同话术时误判。

生产当前仍为 `472a3ad`，本轮没有修改生产容器、配置或数据库业务数据。

## 二、真实问题证据

- 近 72 小时 8 个好友通过任务：仅 1 个在 5 秒内发出邀约，5 个延迟约 6–22 分钟，2 个始终未发。
- 线上日志显示好友通过回调没有 `chatId`，旧逻辑为 `[欢迎语] ok=false code=-1 via=extId`；候选人先发消息后才出现 `via=chatId` 成功。
- 真实图片回调为 `type=11`、`payload.content=b1dca371...`，旧逻辑把它当候选人文本并回复“您好，请问有什么可以帮您”。
- 候选人说“这周四15.30可以吗”时，旧规则只保留“周四”；模型还曾把日期写错。
- 面试已约成后，候选人连续回复“好”“嗯嗯，好的”，AI 连续发送三条无信息量的客套话。

## 三、影响面与处理

| 影响面 | 处理 | 回归重点 |
| --- | --- | --- |
| 好友通过回调 | 无 `chatId` 时走 `sendByWecom` | 回调识别、主动发送、幂等状态 |
| 秒回发送结果回调 | 用 `welcomeRequestId` 关联任务；异步失败退回重试 | 不把一次异步失败直接转人工 |
| Mongo 任务模型 | 新增尝试次数、错误、请求 ID、发送时间、通知标记 | 全部为可选/有默认值，兼容存量 |
| 候选人消息入口 | 非文本先过滤 | 图片/系统事件不进模型、不回消息 |
| 确认/改期/拒绝状态 | 纯礼貌确认静默 | 带问题的“好的，那薪资多少”仍继续处理 |
| 时间解析 | 支持 `15.30`、`这周四` | 原始时间不丢，confirm/reschedule guard 不回退 |
| HR 主动接管 | 非 AI 回声的 `isSelf=true` 消息立即转人工 | 同候选人 AI 回声不误转；跨候选人同话术不漏转 |
| 服务启动 | 新增每 10 秒欢迎语补偿扫描 | 空库启动、健康检查、容器稳定 |

确认、改期、拒绝、转人工、日历和表格回填的既有动作代码未重构；本轮只在进入模型前、欢迎语发送路径和发送结果关联处做外科式修改。
